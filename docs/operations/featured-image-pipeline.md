# Featured image パイプライン (W1.1–W1.2 準備)

WordPress のカテゴリ一覧・記事一覧に並ぶ **NO IMAGE** を、記事テーマの伝わるアイキャッチ
(featured image) に置き換えるための **仕様と試作対象** をまとめる。

この段階では画像をまだ作らない・載せない。

- WordPress への書き込み (メディアのアップロード・featured image の設定) はしない
- 全 25 記事への展開、新規記事フローへの自動組み込み、画像の大量生成はしない
- DB のスキーマ変更は無い。C8 / T6 / Threads worker には触れない

関連ファイル (いずれも git で管理する):

- 仕様 (この文書): `docs/operations/featured-image-pipeline.md`
- 試作 4 記事の機械可読な入力: [`featured-image-pilot-manifest.json`](featured-image-pilot-manifest.json)
- 制作ブリーフ (画像生成・組版をする人がそのまま使う): [`featured-image-pilot-prompts.md`](featured-image-pilot-prompts.md)

## 1. 現状把握 (2026-09-25、公開ページを読むだけで確認)

### テーマ

- **Cocoon** (`cocoon-master`) + 子テーマ `cocoon-child-master`。
- `body` に `thumb-wide` → Cocoon の「サムネイル比率: ワイド (**16:9**)」設定。
- 画像の要素は `object-fit: cover`。16:9 以外の画像は **中央でトリミング** される。
- 現状の NO IMAGE はテーマ同梱の `no-image-320.png` (640×360) / `no-image-160.png`。
  どちらも 16:9。

### 表示される場所と実寸

| 場所 | 表示サイズ (CSS px) | 比率 | 備考 |
| --- | --- | --- | --- |
| カテゴリ一覧・トップの記事カード (PC, 1280px 幅) | **320 × 180** | 16:9 | 左上にカテゴリラベル (62 × 22) が **画像に重なる** |
| 同 (スマホ, 375px 幅) | **126 × 71** | 16:9 | カテゴリラベル (58 × 17) が幅の約 46%・高さの約 24% を覆う |
| 個別記事の関連記事カード | 160 × 90 | 16:9 | |
| 個別記事の前後ナビ | 120 × 68 | 16:9 | |
| 個別記事の本文上アイキャッチ | (現状は非表示) | — | `eye-catch-wrap display-none`。featured image が無い間は隠れている。設定後に表示されるかは試作で確認する |
| OGP / X カード | 1200 × 630 (推奨) | 1.91:1 | 現状は `og:image` がテーマの `screenshot.jpg` (880 × 660)。`twitter:card = summary_large_image` |

**一番厳しいのはスマホの一覧 (126 × 71)** である。仕様はここで読めることを基準にする。

## 2. デザイン仕様

### 2.1 推奨サイズ

| | サイズ | 理由 |
| --- | --- | --- |
| **第一候補 (マスター)** | **1200 × 675 px (16:9)**、PNG または高品質 JPEG / WebP | テーマの 16:9 と一致しトリミングされない。PC 一覧 (320×180) の約 3.75 倍で Retina にも足りる |
| OGP 用 (必要なら派生) | 1200 × 630 | マスターの上下 22.5px ずつを落とすだけで作れる (安全領域の外) |
| X の 2:1 表示 | 1200 × 600 相当 | 上下 37.5px ずつ切れても安全領域の外 |

1 枚のマスター (1200×675) だけを作り、OGP でも同じ画像を使っても崩れないように作る。

### 2.2 安全領域 (1200 × 675 基準)

```
0                                                        1200
┌────────────────────────────────────────────────────────┐ 0
│ 外周マージン (上下 60px / 左右 72px) : 文字・重要要素を置かない │
│ ┌──────────────────┐                                   │
│ │ ラベル予約域        │  ← カテゴリラベルが重なる         │
│ │ 左上 560 × 170     │    (スマホで幅 46%・高さ 24%)     │
│ └──────────────────┘                                   │
│                                                        │
│   見出し (1 フレーズ)           モチーフ               │
│   補助語                                               │
│                                                        │
└────────────────────────────────────────────────────────┘ 675
```

- **外周マージン**: 上下 60px (約 9%)、左右 72px (6%)。OGP (1.91:1) と X (2:1) の上下の
  切り落とし (最大 37.5px) を含めて余裕を取る。
- **ラベル予約域**: 左上 **560 × 170 px** (幅 47%・高さ 25%)。カテゴリラベルが重なるので、
  ここには次のものを **置かない**: 文字 (見出し・補助語とも)、顔・人型、**主モチーフの中心**。
  主モチーフの端がかかるのは構わないが、何のモチーフかを決める部分 (中心・最も目を引く形)
  はこの外に出す。この領域は背景 (色・模様) と、主モチーフから伸びる線や面の端だけにする。
- 見出しは **左下寄り** に置く (ラベルの下、y = 230〜615 の範囲)。

### 2.3 基本レイアウト (第一候補 = 案 A)

- 左 55%: 見出し (1 フレーズ) + 補助語。左揃え。縦方向は下寄り。
- 右 45%: 記事テーマを表すモチーフ (図形・アイコン的な図解)。右端のマージンは守る。
- 背景: 明るい無地、またはごく薄い幾何学パターン。モチーフの後ろに薄い面を置いてよい。
- 下端に、ジャンルのアクセント色の細い帯 (高さ 8〜12px) を置いてよい。一覧で並べたときの統一感を出す。

### 2.4 文字ルール

- **1 フレーズ + 必要なら小さな補助語** だけ。記事タイトル全文は載せない
  (一覧ではタイトルが画像の横に別に出る)。
- **画像内の文字は、一覧のタイトルと役割を重ねない。** タイトルは「何の記事か」を正確に
  言う役 (例: 「ChatGPT法人プラン｜プラン別の料金と選び方」)。画像の見出しは「一目で何を
  得られるか」を示す短いフックの役 (例: 「法人プラン比較」)。タイトルの前半をそのまま切り
  出しただけの文字 (「ChatGPT法人プラン」) や、タイトルの言い換えだけの文字は避け、記事で
  得られること (比較・要点・入門・選び方など) が伝わる語にする。
- 見出し: **1 フレーズ・全角 8 文字程度まで**。1 行に収まるのは、見出しの列 (幅 約 570px) で
  Bold 100px なら **全角 5 文字程度** (実測: 「法人プラン」104px で 520px、「法人プラン比較」96px で
  672px)。長い場合は 2 行まで (1 行は列の幅に収まる長さ)。例: 「法人プラン / 比較」。
  例: 「AI業務効率化」「法人プラン比較」「AIエージェント / とは」「Enterpriseの要点」。
- 見出しの文字の高さは **96〜120px** (太字)。スマホ一覧 (71px 高) で約 10〜13px に
  なる最低限。**90px 未満は禁止**。
- 補助語: 40〜48px。PC 一覧 (約 11〜13px) で読める大きさ。スマホでは読めなくてよい
  (意味の中心を補助語に持たせない)。補助語も 1 行・全角 12 文字以内。
- フォント: ゴシック体 1 書体 (例: Noto Sans JP)。太さは見出し Bold / 補助語 Medium の
  2 段階まで。斜体・袋文字・影付き・縁取りの多用はしない。
- **画像生成モデルに日本語の文字を描かせない。** 文字は必ず組版ソフトかスクリプト
  (SVG / Pillow など) で後から重ねる。生成モデルは崩れた擬似文字を描きやすい。
- 価格・日付・数値は載せない (記事の「2026年9月時点」の条件が画像から落ち、古くなっても
  直しにくいため)。

### 2.5 配色ルール

- ベース: 背景 `#F5F7FA` (ごく薄いグレー)、見出しの文字 `#12263F` (濃紺)。
  背景と文字のコントラストは WCAG AA (4.5:1) を十分に超える。
- アクセントは **1 枚につき 1 色**。モチーフの面・線・下端の帯にだけ使い、小さな文字には使わない。
- アクセントは **記事ジャンル (トピックの系統)** ごとに決める (記事ごとにバラバラにしない)。

| 系統 | アクセント | 使う記事の例 |
| --- | --- | --- |
| AI・業務効率化 (総論) | ティール `#0D9488` | AI業務効率化、業務効率化ツール |
| AI エージェント・生成 AI | インディゴ `#4F46E5` | AIエージェント、生成AIツール |
| ChatGPT の法人利用 (料金・プラン) | ブルー `#2563EB` | ChatGPT法人プラン |
| ChatGPT の法人利用 (導入・管理) | スレートブルー `#334E68` + ブルー `#2563EB` | ChatGPT Enterprise |
| 議事録・文字起こし | スカイ `#0284C7` | AI議事録、文字起こしAI |
| CRM・SFA・営業 | オレンジ `#EA580C` | CRM、HubSpot、CRM SFA違い |
| RPA・自動化ツール | グリーン `#16A34A` | RPA、Make |
| ガイドライン・ガバナンス | スレート `#475569` | 生成AIガイドライン、AIガバナンス |

- 同じ系統の記事が一覧で隣り合う場合は、**モチーフ** で差を出す (色は同じ系統のまま)。
- 蛍光色・強いグラデーション・多色の虹色は使わない。

### 2.5.1 似た記事が一覧で並ぶときの見分けルール

同じ製品・同じ系統の記事が一覧で隣り合うと、色が近いぶん見分けにくい。次の順で差を出す。

1. **記事で得られることの違いを、モチーフの「形の種類」で分ける。** 色の濃淡だけに頼らない
   (スマホの 126×71 では色の差がほとんど見えない)。
2. **見出しの語を、得られることの違いがわかる語にする** (「比較」と「要点」のように、
   片方をもう片方の言い換えにしない)。
3. 色は同じ系統のまま、明るさ (明るい / 深い) で補助的に分ける。

現在の試作で該当する組 (ChatGPT の法人利用 2 本):

| 記事 | 強く出す印象 | モチーフの形 | 色の明るさ |
| --- | --- | --- | --- |
| ChatGPT法人プラン (「**法人プラン比較**」) | **比較感**: 選択肢を横に並べて見比べる | 横に並ぶ 3 枚のカード (段差・並列・比べる向き)。シートの人型 | 明るいブルー |
| ChatGPT Enterprise (「**Enterpriseの要点**」) | **管理・セキュリティ感**: 組織で統制して使う | 1 枚の管理パネル (スイッチ・ユーザー一覧) + 鍵 + 盾の小さな記号 | 深いスレートブルー |

「並べて見比べる横長の構図」と「1 つの管理画面を守る縦にまとまった構図」で、形だけでも
区別できるようにする。

### 2.6 記事の型ごとのモチーフ例

モチーフは **フラットな図形・アイコン的な図解** を基本にする (写真は使わない)。

| 記事の型 (`article_type`) | モチーフ例 |
| --- | --- |
| `informational` (要点と注意点) | チェックリスト + 注意マーク、2 つに分かれる流れ図 |
| `pricing` (料金・プラン) | 段の違うプランカード 3 枚、利用者 (シート) を表す人型の小アイコン。**金額は描かない** |
| `category_landing` (基礎知識) | 中心のノードから線でつながる概念図 (マインドマップ風) |
| `comparison_listicle` / `recommendation_roundup` | 並んだパネル・比較表の抽象図・チェック列 |
| `how_to` | 番号付きのステップと矢印 |

テーマ別の補助モチーフ: 議事録 = 波形 + 文書の行、CRM = ファネル / パイプライン、
RPA・Make = 連結したブロックの流れ、ガバナンス = 文書 + チェック + 盾。

### 2.7 禁止事項

- 記事タイトル全文のベタ載せ、文字の詰め込み、90px 未満の見出し
- ラベル予約域 (左上 560 × 170) と外周マージンへの文字・重要要素の配置
- **各社の公式ロゴ・商標のマーク・製品画面のスクリーンショット** (OpenAI などのロゴを含む)。
  実在の製品画面に見える偽の UI も作らない
- 価格・日付・「No.1」「最強」などの数値や順位の断定、煽り表現
  (Threads のポリシーと同じ: 「神ツール」「絶対に」「革命的」「圧倒的に」「誰でも簡単に」「必ず儲かる」)
- ストックフォト感の強い人物写真、顔写真の必須化、握手・スーツの定番写真
- 生成モデルに描かせた日本語の文字、崩れた擬似文字
- 絵文字、過剰な装飾、ネオン・強いグラデーション
- アフィリエイトを連想させる誘導表現 (「今すぐ申し込み」など)

## 3. デザイン案の比較

| | 案 A: 左テキスト + 右モチーフ (推奨) | 案 B: 全面モチーフ + 下帯テキスト | 案 C: 上下 2 分割の色帯 |
| --- | --- | --- | --- |
| 構成 | 明るい背景。左下に見出し、右にモチーフ | 濃い背景に大きなモチーフ。下 30% の帯に白文字 | 上 60% がアクセント色の面 + 小さなモチーフ、下 40% が白地に見出し |

| テーマ差 | モチーフで十分に出る | 最も出る | 出にくい |
| 実務的・清潔なトーン | 合う | やや重い | 合うが単調 |

**案 A を第一候補** にする。試作では 1 記事だけ案 B も作り、一覧に並べて比べてよい。

### 試作の確認項目 (次の段階)

## 5. W1.4 本番適用の記録 (2026-09-25)

人が試作 4 枚を承認し、本番 WordPress への適用を明示的に許可した。使ったファイルは
`artifacts/featured-images/pilot/` の 1200×675 WebP (git 管理外。承認時の
`wordpress-apply-manifest.json` の SHA-256 と一致を確認済み)。

### 適用結果

| article | slug | WordPress post | 元の featured_media | media ID | ファイル | 設定した主体 |
| --- | --- | --- | --- | --- | --- | --- |
| 25 | ai-business-efficiency | 78 | 0 | **100** | featured-25-ai-business-efficiency-1.webp | この適用 (canary、upload) |
| 23 | chatgpt-business-plans | 74 | 0 | **98** | featured-23-chatgpt-business-plans.webp | 別の主体 (事前 upload 済みの media) |
| 24 | ai-agents | 76 | 0 | **97** | featured-24-ai-agents.webp | 別の主体 (事前 upload 済みの media) |
| 20 | chatgpt-enterprise | 72 | 0 | **96** | featured-20-chatgpt-enterprise.webp | 別の主体 (事前 upload 済みの media) |

- application の article_id と WordPress の post ID は一致しない (slug で解決し、タイトルの完全
  一致を確かめてから書いた)。
- 適用の道具: `scripts/apply_featured_image.py` (既存の `WordPressClient` の exact 契約。
  upload → media の read-back → alt/title → `{"featured_media": id}` → post の read-back)。
- 時刻 (JST): 17:18 に書く前の状態を保存 (25 post、すべて publish、featured image なし)。
  17:18:32 に article 25 の canary を適用。17:20:33〜17:20:50 に、この適用とは別の主体が
  media 96〜98 に alt/title を付けて 23 / 24 / 20 に設定していた (17:43 の確認で判明。
  この適用はそれを上書きしていない)。
- 書く前と後の全 post の比較: 変わったのは post 72 / 74 / 76 / 78 の `featured_media` と
  `modified_gmt` だけ。タイトル・slug・本文・抜粋・状態・公開日・カテゴリ・タグは 25 post
  とも変わっていない。

### 確認

| 項目 | 結果 |
| --- | --- |
| 記事ページ / カテゴリ一覧 | 200 |
| 一覧のカード (PC 320×180) | 4 枚とも 640×360 の派生画像。NO IMAGE ではない |
| 一覧のカード (スマホ 126×71) | 見出しが読める。カテゴリラベルは左上の空白にだけ重なる |
| 並べたときの印象 | 同じ系統に見え、色で主題の違いがわかる。23 (横並びのカード) と 20 (盾で守る 1 枚のパネル) は形だけで見分けられる |
| 禁止事項 | ロゴ・製品画面・金額・日付・擬似文字なし。重要な要素の切れなし |
| 本文上のアイキャッチ | Cocoon が featured image を本文上に表示するようになった (設定は変えていない)。見た目は問題なし |
| `og:image` / `twitter:image` | 4 記事とも記事の画像 (フルサイズ) に切り替わった。`twitter:card = summary_large_image` |

### 気づいたこと・次の対応

1. **重複した media**: media library に同じ画像が 2 つある。事前 upload の **99**
   (`featured-25-ai-business-efficiency.webp`、どこにも使われていない) と、canary で upload
