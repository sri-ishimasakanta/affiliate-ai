# 承認の門のチェックリスト

AIに作業を任せる前に、書き込み先ごとに次の項目を確かめます。「はい」にできない項目があれば、
その書き込みはまだ自動にしない、という判断の材料にしてください。

## 1. 分ける

- [ ] 書き込み先 (記事・投稿・メール・設定・外部のサービス) を一覧にした
- [ ] それぞれを 5 つの段階 (A 読むだけ / B 決めた上限の中で自動 / C 1 件ずつ人が承認 /
      D 初回だけ人が有効にする / E 自動にしない) のどれかに置いた
- [ ] 「提案を認める」ことと「書き込みを認める」ことを別の判断にした
- [ ] 一度にまとめて承認する入口 (すべて承認) を作っていない

## 2. 承認を内容に結びつける

- [ ] 承認は、承認したときの内容の hash (指紋) に結びついている
- [ ] 内容が 1 文字でも変われば、承認は効かなくなり、もう一度承認が要る
- [ ] 承認は「この内容なら出してよい」であって「今すぐ出す」ではない、と決めている
- [ ] 承認した人・時刻・内容の hash が記録に残る

## 3. 書き込みを安全にする

- [ ] 書き込みの前に、相手側の今の状態が承認のときと変わっていないかを確かめる
- [ ] 書き込みの後に読み戻し、承認した内容と同じかを確かめる
- [ ] 結果が分からない (通信が途中で切れた等) ときは、成功として記録しない
- [ ] 止まっていた分をまとめて一気に出す「取り戻し」をしない
- [ ] 新しい書き込みの形は、既定を「無効」にし、最初の 1 回を人が確かめてから有効にする

## 4. 記録と通知

- [ ] 記録は消さない。直すときは、古い記録を指す新しい記録を足す
- [ ] 通知は、行動が要るときだけにする。正常は知らせない
- [ ] 同じ問題は 1 つの通知にまとめ、直ったら閉じる
- [ ] 数字が少ないうちは、結果を「効いた」「効かない」と書かない

## 5. 秘密

- [ ] パスワード・トークンは設定の例や記録に書かない (環境ごとの秘密の置き場だけ)
- [ ] 公開する文章に、手元のパス・端末名・内部の識別子が入っていない
- [ ] 外部のサービスの権限は、必要な最小にしてある
