# 通知の設計チェックリスト

## 分ける

- [ ] 点検の結果を「情報 / 注意 / 異常」に分けた
- [ ] 「正常に終わった」は通知しない
- [ ] 情報は、まとめの画面や報告だけに出す
- [ ] 人の承認待ちなどの「待ち」は、長く残りすぎたときだけ注意にする

## まとめる

- [ ] 問題ごとに、日付を含まない変わらない名前を決めた
- [ ] 同じ名前の問題は1つの記録にまとめ、回数と最後に見た時刻だけを更新する
- [ ] 同じ問題を毎日知らせない

## 知らせ直す・閉じる

- [ ] 知らせ直しの間隔を決めた (例: 1週間)
- [ ] 人が確認済みにした問題は知らせ直さない
- [ ] 直った問題は、次の点検で自動的に閉じる
- [ ] 自動で閉じてよいのは、点検が自分で作った問題だけ

## 時間

- [ ] 夜中に対応できない通知は、朝の決まった点検でまとめて出す
- [ ] 通知の失敗 (送れなかった) は、記録に残して次の点検で分かるようにした

## 見直す

- [ ] 1か月に1回、読まずに閉じた通知が無いかを見直す
- [ ] 読まれない通知は、情報に下げるか、条件を見直す
