# 「今の状態」レポートを作る・読むときの手引き

## なぜ必要か

AIの支援を受けながら開発していると、前の会話のメモや古いドキュメントが「今もそうだ」と
扱われがちです。ところが本番は、その後の変更で変わっています。古いメモを信じて作業すると、
すでに有効な機能をもう一度有効にしようとしたり、止まっているものを動いていると思い込んだり
します。

## 作るときの3つの約束

1. **観測した事実は、古い文章より強い。** 本番を読んで確かめた値と、ドキュメントの記述が
   違えば、観測した値を採ります。
2. **レポートは本番を変えない。** 食い違いを見つけても、レポートを作る作業の中で本番を
   直してはいけません。直すのは記録の側 (ドキュメント・メモ) か、別の作業として人が決めます。
3. **読めなかったものは「読めなかった」と書く。** 推測で埋めません。「不明」は立派な結果です。

## 読むときのコツ

- まず「止めるべき問題」を読みます。無ければ次に進んでかまいません。
- 「鮮度」が古い事実は、使う前に確かめ直します。
- 「ずれ」の欄は、ドキュメントを直す作業の一覧として使えます。
- 「人の判断待ち」は、AIに任せず人が決めることです。AIに進めさせる前に確認します。

## いつ作るか

毎日作る必要はありません。作業の区切り (大きな変更の前後、担当や会話が変わるとき) に作れば
十分です。定期的に作るのは、必要が出てからで間に合います。

## この手引きで言えないこと

このレポートで開発が速くなる、とは言えません。確かめられるのは、古い情報を信じて誤る機会が
減る、ということだけです。
